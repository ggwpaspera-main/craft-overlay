# Архитектура MVP: парсер предметов PoE2

Статус: **M0 завершён, M1 — первый срез парсера готов**. Стек: Electron + TypeScript (Electron — позже).
MVP: парсер скопированного текста предмета. Без оверлея, trade API и OCR.

Связанные документы:

- [FORMAT-RU.md](FORMAT-RU.md) — разобранный формат русского advanced-copy и модель данных.
- [REFERENCES.md](REFERENCES.md) — справочные данные из `default-workspace`.

---

## 1. Цель и границы MVP

**Вход:** текст предмета, скопированный в игре (`Ctrl+C` — basic, `Ctrl+Alt+C` — advanced).
**Выход:** нормализованный JSON: класс, категория, редкость, имя/база, ilvl, свойства, требования, сокеты, моды с типом/тиром/тегами/значениями/диапазонами, руны, флаги, лор/описание, диагностика.

В MVP входит:

- разбор структуры и заголовка;
- классификация и извлечение свойств/требований;
- advanced-моды: `{ Префикс|Суффикс|… (Уровень: N) — теги }` + строки статов;
- значения и диапазоны (`42(39-42)%`, `14.3(13.1-18)`, `-4`);
- состояния (`Очернённое` → desecrated), руны `(rune)`, фиксированные значения;
- флаги (`Осквернено`), лор уникальных, описание путевых камней;
- `unknownLines` + `warnings`: ничего не теряем молча.

Не входит: цены, сеть, OCR, Electron UI, оверлей, база предметов, автообновление.

## 2. Почему парсер первым

- Чистая функция «текст → JSON», без окон, хуков и сети.
- Тесты за секунды; ломается только при изменении формата, а не при обновлении Electron.
- Переиспользуется в CLI, будущем UI, price-check и крафт-калькуляторе.
- Хороший полигон для TypeScript: регулярки, структуры, тесты.

## 3. Инварианты

1. **Никогда не терять данные молча.** Неизвестная строка → `unknownLines`; подозрение → `warnings`.
2. **Не угадывать.** Из basic copy нельзя определить префикс/суффикс — ставим `unknown`, а не догадку.
3. **Словарь отдельно от логики.** В коде нет русских строк, только ключи `locale/ru.ts`.
4. **Формат важнее смысла.** На MVP не нужно понимать, что делает мод; нужно выделить структуру, числа и диапазоны.
5. **Парсер не бросает исключение на странном тексте.** Возвращает `ParseResult` с `ok: false` и причиной.
6. **Версионирование.** `parserVersion` + snapshot-тесты, чтобы патчи игры не ломали незаметно.

## 4. Слои приложения

```
┌──────────────────────────── Electron (позже) ───────────────────────────┐
│  main (Node)                  preload              renderer             │
│  ├─ окна, оверлей            contextBridge         UI-панель            │
│  ├─ глобальный хоткей   ───► parseItem(text)  ◄───  карточка            │

│  └─ настройки, trade (M6)                                               │
└──────────────────────────────────────────────────────────────────────────┘
                    ▲ импорт
              src/core (чистый TS)
              ├─ parser.ts        parseItemText(raw, locale)
              ├─ sections.ts      нормализация, разбиение по "--------"
              ├─ header.ts        класс/редкость/имя/база
              ├─ properties.ts    свойства и требования
              ├─ modifiers.ts     advanced-блоки, basic-моды, значения
              ├─ flags.ts         Осквернено / ...

```

На M1 существует только `src/core` + CLI + тесты. Electron добавляется на M3, когда парсер стабилен.

## 5. Поток парсинга

1. **Нормализация:** BOM, `\r\n` → `\n`, trim хвостовых пробелов, сохранить пустые строки.
2. **Разбиение:** по строке ровно из 8 дефисов `--------`.
3. **Заголовок:** `Класс предмета`, `Редкость`, 1–2 строки имени/базы.
4. **Классификация:** класс → `category/subtype`, редкость → `rarity` по словарю; неизвестное → warning.
5. **Секции:** свойства, требования, сокеты, ilvl, флаги — по меткам и паттернам.
6. **Моды:**
   - advanced-заголовок открывает `ModifierGroup`; строки до следующего заголовка/секции — `lines[]`;
   - hybrid = одна группа с несколькими строками;
   - состояния из заголовка (`Очернённое`) и из basic-маркеров;
   - текст стата чистится от диапазонов и маркеров, но ролл сохраняется;
   - руны `(rune)` — отдельный список;
   - `— Неизменяемое значение` → `fixedValue: true`, срезается из текста.
7. **Хвост:** лор уникальных → `flavourText`; описание путевых камней → `description`; остальное → `unknownLines`.
8. **Диагностика:** собрать warnings; вернуть `ParseResult`.

Подробности формата — в [FORMAT-RU.md](FORMAT-RU.md).

## 6. Локаль

Клиент на этой машине русский (`[LANGUAGE] language=ru`, локализованные названия зон в `Client.txt`), поэтому первый словарь — `ru`. Второй — `en` (для тестов и будущего trade API).

- Канонические ключи в JSON всегда английские: `energyShield`, `prefix`, `corrupted`.
- Исходные строки сохраняются рядом (`label`, `headerRaw`, `tags`).
- Словарь — данные, а не код: `locale/ru.ts` экспортирует объект с метками, редкостями, классами, маркерами.
- Канонизация названий/тегов для trade — отдельный слой `canonical.ts` (позже), на MVP теги хранятся как в тексте.

## 7. Тесты и фикстуры

- `fixtures/ru/*.txt` — реальные тексты (basic и advanced раздельно).
- Ожидаемый JSON — snapshot рядом с фикстурой.
- `Vitest`, параметризованные тесты по всем фикстурам.
- Целевой корпус MVP: **40+ предметов**:
  - оружие (physical/elemental, одноручное/двуручное), броня (ES/armour/evasion/гибрид), бижутерия;
  - фласки/чармы, джевелы, waystones/tablets, гемы, валюта, руны/соулкоры;
  - unique (лор), corrupted, desecrated, fractured, unidentified.
- Отдельные тесты «плохого» входа: пусто, мусор, обрезанный текст, не предмет.

## 9. Будущее (после MVP)

- **M3 Electron:** окно с вставкой текста и карточкой; `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- **M4 хоткей/буфер:** `globalShortcut`/low-level hook, чтение буфера, отправка `Ctrl+C` (по возможности — без отправки, силами пользователя).
- **M5 оверлей:** прозрачное `alwaysOnTop`-окно, `setIgnoreMouseEvents(true)`, переключение интерактивности по хоткею; игра в borderless (у нас `borderless_windowed_fullscreen=true`).
- **M6 trade:** поиск по trade2, канонизация RU→EN, rate limiting, кэш.

## 11. Риски

- **Формат меняется патчами.** Фикстуры, snapshot-тесты, версия парсера.
- **Локализация.** Часть строк может остаться английской; словарь расширяем по образцам.
- **Баг advanced copy.** Пропадают пометки `(fractured)/(desecrated)/(implicit)` — поддерживаем basic copy и фиксируем ограничения.
- **Неизвестные категории.** Оружие/гемы/валюта требуют отдельных образцов.
- **Соблазн UI.** MVP — только парсер.
- **AI-зависимость.** Код разбираем файл за файлом, чтобы проект оставался понятным.
