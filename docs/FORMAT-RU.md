# Формат предметов PoE2: русский advanced-copy

Источник: 4 реальных образца, скопированных в игре 2026-11-05 через `Ctrl+Alt+C` (advanced item copy), клиент RU.
Фикстуры: [`fixtures/ru/`](../fixtures/ru/).

Документ фиксирует **наблюдаемый** формат. Всё, что не подтверждено образцами, помечено `TODO` и не должно угадываться в коде.

---

## 1. Общая структура

Текст предмета — это секции, разделённые строкой ровно из 8 дефисов:

```
<заголовок>
--------
<секция>
--------
<секция>
...
```

- Разделитель: `--------` (8 дефисов; пробелы по краям обрезаются).
- Внутри секций могут быть пустые строки (в advanced-copy между группами модов их нет, но парсер обязан их терпеть).
- Порядок секций не гарантирован: парсер не должен полагаться на позицию, кроме заголовка (всегда первая секция) и хвостовых описаний/лора.

## 2. Заголовок

```
Класс предмета: Шлемы
Редкость: Редкий
Драконий спаситель
Тиара Камасы
```

- `Класс предмета: <строка>` — локализованный класс.
- `Редкость: <строка>` — локализованная редкость.
- Далее 1–2 строки имени/базы:
  - редкий и уникальный предмет — **2 строки**: имя, затем база;
  - путевой камень — **2 строки**: имя, затем база с тиром `Путевой камень (Ур. 15)`;
  - magic/normal — предположительно **1 строка** (`TODO`: нужны образцы);
  - валюта/камень — предположительно **1 строка** (`TODO`).

Редкости, встреченные в образцах: `Редкий`, `Уникальный`.
`TODO`: точные строки для normal/magic/currency/gem.

## 3. Секции

### 3.1. Свойства

```
Качество: +26% (augmented)
Энергетический щит: 512 (augmented)
```

Формат: `<метка>: <значение> (augmented)`.

- `(augmented)` — английский маркер, означает «значение изменено» (качеством/модами). Может отсутствовать.
- `Качество` — особое свойство: из него извлекается `quality: number`.
- Остальные свойства кладутся в `properties[]` с каноническим `key`, исходной `label` и `values[]`.

Наблюдённые свойства:

| Русская метка | Канонический ключ |
|---|---|
| `Качество` | `quality` (отдельное поле) |
| `Энергетический щит` | `energyShield` |
| `Доступно возрождений` | `waystoneRevives` |
| `Размер групп монстров` | `monsterPackSize` |
| `Эффективность монстров` | `monsterEffectiveness` |
| `Шанс выпадения путевого камня` | `waystoneDropChance` |

### 3.2. Требования

```
Требуется: Уровень 75, 107 Инт
Требуется: Уровень 24
```

- Токены через `, `.
- `Уровень N` → `{ key: 'level', value: N }`.
- `N Инт` → `{ key: 'int', value: N }`; аналогично `Сил`/`Лов` (TODO: проверить сокращения).
- Возможен маркер `(unmet)` (в образцах не встретился): `TODO`, вероятно английский.

### 3.3. Гнёзда

```
Гнезда: S S
Гнезда: S
```

- Токены после двоеточия; в образцах — буквы `S`.
- Смысл букв (`S` = socket? тип?) не подтверждён. Храним как массив строк, не интерпретируем.

### 3.4. Уровень предмета

```
Уровень предмета: 80
```

→ `itemLevel: 80`.

### 3.5. Модификаторы (advanced)

Advanced-copy добавляет заголовки групп модов:

```
{ Префикс "Папский" (Уровень: 1) — Здоровье, Энергетический щит }
42(39-42)% увеличение энергетического щита
+45(42-49) к максимуму здоровья
```

Формы, встреченные в образцах:

```
{ Префикс "Имя" (Уровень: N) — Тег1, Тег2 }
{ Суффикс "Имя" (Уровень: N) — Тег1, Тег2 }
{ Очернённое Префикс "Имя" (Уровень: N) — Тег1, Тег2 }
{ Собственное свойство — Тег }
{ Уникальное свойство — Тег1, Тег2 }
{ Улучшение }
```

Общая грамматика:

```
{ [<состояние> ] <вид> ["<имя аффикса>"] [(Уровень: <тир>)] [— <теги>] }
```

- `<вид>`:
  - `Префикс` → `kind: 'prefix'`;
  - `Суффикс` → `kind: 'suffix'`;
  - `Собственное свойство` → `source: 'implicit'`;
  - `Уникальное свойство` → `source: 'unique'` (явный мод уникального предмета, без префикс/суффикс);
  - `Улучшение` → `source: 'enchantment'` (семантика уточняется; встретилось на осквернённом шлеме).
- `<состояние>` перед видом: `Очернённое` → `states: ['desecrated']`.
- `(Уровень: N)` — тир аффикса (`tier`). Не путать с `Уровень предмета` и `Требуется: Уровень`.
- Теги — через `, `; могут отсутствовать.
- Группа продолжается, пока не начался следующий заголовок, флаг или секция.
- **Один аффикс может содержать несколько строк статов** (hybrid): например, `Папский` даёт 2 строки. Это одна группа с `lines[]`.
- В образцах у путевых камней теги в заголовке отсутствуют, а тир есть.
- В образцах заголовки идут подряд, без пустых строк между группами.

### 3.6. Строки статов

Примеры:

```
42(39-42)% увеличение энергетического щита
+45(42-49) к максимуму здоровья
Регенерация 14.3(13.1-18) здоровья в секунду
35% повышение скорости передвижения
-4 входящего физического урона при получении удара от атак
Область содержит участки заряженной земли — Неизменяемое значение
```

Правила:

- Значение ролла: `[+-]?\d+(?:[.,]\d+)?`.
- Диапазон: `(<min>-<max>)` сразу после ролла; внутри может быть `-`, `—` или `–`; числа могут быть отрицательными.
- Ролл может отсутствовать, если есть только диапазон (`(-4—-3)%` — гипотетически; в `_ws.txt` такие шаблоны есть).
- `%` и другие единицы остаются в тексте.
- `— Неизменяемое значение` в конце строки — маркер «фиксированное значение, без ролла». Срезается из `text`, ставит `fixedValue: true`. Встречается не у всех фиксированных модов (`35% повышение скорости передвижения` — без маркера).
- Строка может не содержать чисел вообще (`Монстры уклончивы`, `Касание Ворона (rune)`).
- Из строки строится `text` — она же, но без диапазонов и без маркеров. Ролл сохраняется: `42% увеличение энергетического щита`.

### 3.7. Руны

```
+22% к сопротивлению огню (rune)
Касание Ворона (rune)
```

- Строки с суффиксом `(rune)` — рунные моды.
- Могут содержать числа и диапазоны, могут быть текстовыми.
- Хранятся отдельно (`runes[]`), потому что у них нет префикса/суффикса/тира.
- В шлеме руны идут отдельной секцией между `{ Улучшение }` и явными модами.
- В обуви руна — единственная строка в секции.

### 3.8. Флаги

```
Осквернено
```

- Отдельная строка-флаг → `flags.corrupted = true`.
- `Осквернённая граница` в имени — не флаг; сравниваем строку целиком, не подстроку.
- `TODO`: остальные флаги (`Расколото`, `Освящено`, `Отзеркалено`, `Разделено`, `Неизменяемо` и т.п.) — нужны образцы.

### 3.9. Уникальные предметы: лор

Уникальный амулет заканчивается секцией без заголовков:

```
Безумный гнев раздавит мир,
коварно ложь его стреножит,
беспечность спешки длань приложит
и в темноте его пленит.
```

- Это flavour text; строки не парсятся как моды.
- Признак: rarity `unique` + последняя секция без заголовков/флагов/свойств.
- Сохраняется как `flavourText: string[]`.

### 3.10. Путевые камни: описание

```
Можно использовать в Машине картоходца, чтобы войти на карту. Путевые камни одноразовые.
```

- Хвостовая секция-описание; сохраняется как `description: string[]`.
- Не является модом.

## 5. Выходная модель

```ts
export type Locale = 'ru' | 'en';

export type ItemCategory =
  | 'weapon' | 'armour' | 'jewellery' | 'flask' | 'charm'
  | 'jewel' | 'gem' | 'currency' | 'rune' | 'waystone' | 'tablet'
  | 'quest' | 'unknown';

export type Rarity =
  | 'normal' | 'magic' | 'rare' | 'unique' | 'gem' | 'currency' | 'unknown';

export type ModifierSource =
  | 'explicit' | 'implicit' | 'unique' | 'enchantment' | 'rune' | 'unknown';

export type AffixKind = 'prefix' | 'suffix' | 'none';

export type ModifierState =
  | 'fractured' | 'desecrated' | 'crafted' | 'sanctified' | 'unmodifiable' | 'unknown';

export interface ModValue {
  raw: string;          // "42(39-42)%"
  rolled: number | null; // 42; null если ролл не указан
  min?: number;
  max?: number;
}

export interface StatLine {
  raw: string;          // исходная строка
  text: string;         // без диапазонов/маркеров: "42% увеличение энергетического щита"
  values: ModValue[];
  fixedValue?: boolean;
}

export interface ModifierGroup {
  source: ModifierSource;
  kind: AffixKind;
  headerRaw: string;    // "{ Префикс "Папский" (Уровень: 1) — Здоровье, Энергетический щит }"
  affixName?: string;
  tier?: number;
  tags: string[];       // локализованные, как в тексте
  states: ModifierState[];
  lines: StatLine[];
}

export interface ItemProperty {
  key: string;          // energyShield | waystoneRevives | ...
  label: string;        // как в тексте
  values: string[];     // ["512"], ["+22%"]
  augmented?: boolean;
}

export interface Requirement {
  key: 'level' | 'str' | 'dex' | 'int' | 'unknown';
  value: number;
  unmet?: boolean;
}

export interface ParsedItem {
  raw: string;
  locale: Locale;
  parserVersion: string;
  itemClass: string;
  category: ItemCategory;
  subtype?: string;
  rarity: Rarity;
  name?: string;
  baseType?: string;
  itemLevel?: number;
  quality?: number;
  waystoneTier?: number;
  stackSize?: number;
  properties: ItemProperty[];
  requirements: Requirement[];
  sockets: string[];
  modifiers: ModifierGroup[];
  runes: StatLine[];
  flavourText?: string[];
  description?: string[];
  flags: {
    corrupted?: boolean;
    fractured?: boolean;
    desecrated?: boolean;
    sanctified?: boolean;
    mirrored?: boolean;
    split?: boolean;
    unmodifiable?: boolean;
    unidentified?: boolean;
  };
  unknownLines: string[];
  warnings: string[];
}

export interface ParseResult {
  ok: boolean;
  item: ParsedItem | null;
  warnings: string[];
  unknownLines: string[];
}
```

## 8. Приёмочные критерии формата

- Все 4 фикстуры парсятся без исключений.
- У шлема и обуви корректно определяются: имя/база, ilvl, quality, ES, требования, сокеты, 5–6 групп модов с тирами/тегами, гибридные группы, очернённый префикс, руны, `corrupted`.
- У waystone: `waystoneTier: 15`, 4 свойства, моды без тегов, `fixedValue` у «заряженной земли», описание.
- У амулета: `source: 'implicit'` для `Собственное свойство`, `source: 'unique'` для `Уникальное свойство`, лор отдельно, требования без атрибутов.
- Неизвестные строки не теряются: попадают в `unknownLines` с контекстом.
